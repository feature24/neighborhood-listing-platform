Acceptance Criteria
These criteria describe planned behavior for the prototype. Updates and approvals are handled manually through project files.
US1 — Display rental listings
Given an approved sample listing, when a visitor opens the listing page, then its location, rent, availability, and description are displayed.
Given an unapproved listing, when a visitor opens the listing page, then that listing is hidden.
US2 — Update rental information
Given an approved listing, when its rent or availability is changed, reviewed, and published, then the page displays the updated information.
Given an update that fails validation, when publication is attempted, then the invalid update is blocked.
US3 — Check required listing information
Given a listing containing all required fields in the prototype schema, when validation runs, then it passes.
Given a listing missing a required field, when validation runs, then it fails and identifies the missing field.
US4 — Review listings before publication
Given a valid draft listing with recorded approval, when public listing data is prepared, then the listing is included.
Given a draft without recorded approval, when public listing data is prepared, then the listing is excluded.
US5 — Display café promotions
Given an approved café promotion, when a visitor opens the page, then the café name, promotional text, destination link, and “Sponsored” label are displayed.
Given an unapproved promotion, when a visitor opens the page, then the promotion is hidden.
US6 — Check promotion links
Given a promotion with a correctly formatted HTTPS link, when link validation runs, then the format check passes.
Given a missing or incorrectly formatted link, when validation runs, then an error identifies the problem and approval is blocked.
A format check does not prove the destination works. The destination must also be opened and reviewed manually.
US7 — Remove expired promotions
Given an expired promotion, when the maintainer withdraws it and publishes the updated data, then it no longer appears on the page.
Given a withdrawn promotion, when public promotion data is prepared again, then it remains excluded until explicitly reviewed and approved again.
Accessibility Checks
Given a 375-pixel-wide screen, when a visitor browses the page, then text and controls remain readable without horizontal page scrolling.
Given keyboard-only navigation, when a visitor moves through links and controls, then focus is visible, and each control can be operated.
Content Approval Workflow
This workflow applies to rental listings and café promotions.
Draft
Prepare the sample listing or promotion. Keep it unpublished.
Submitted for Review
Check required information, wording, images, and links. Return incomplete content for correction.
Pending Admin Check
Confirm that the content passed validation and review. Check rental details for consistency. Check promotion dates, destination links, and support for promotional claims.
Approved & Published
Record the content ID, reviewer, approval date, and decision. Include only approved content in the public data.
Rejected with Feedback
Record what needs correction. Return the content to Draft, then repeat the review process.
Changes to published content must go through review again. Outdated listings and expired promotions are withdrawn manually.
All approvals in this exercise are simulated. A real project would require approval from the authorized content owner.
Value Proposition
The Neighborhood Listing Platform is a student project designed to bring rental listings and local business promotions into one place. Its proposed value is helping prospective renters find clear property information while discovering businesses around the neighborhood.
For property managers, the platform would provide a consistent way to display rental details, including location, rent, availability, and descriptions. Required information checks and a review process would help prevent incomplete or unapproved listings from being published.
For local café owners, the platform would provide space for approved promotions with current links and clear sponsorship labels. Reviewing promotional information and withdrawing expired offers would help visitors see accurate information.
Visitors would be able to browse rental information and café promotions through readable pages that work on phones and support keyboard navigation.
The Week 8 MVP would use sample content. Updates, approvals, and withdrawals would be managed manually through project files. Accounts, dashboards, payments, and automated publishing are outside the initial scope.
Success would be demonstrated by approved content displaying correctly, invalid records being flagged, updates appearing after publication, and withdrawn promotions staying hidden. Mobile and keyboard checks would also be completed.
These benefits are working hypotheses based on simulated discovery. No real stakeholder interviews or business results are claimed.
